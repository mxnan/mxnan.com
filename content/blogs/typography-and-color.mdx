# Typography & Color System

Complexity impresses your team. Clarity impresses your users.

This system runs on tokens, not hex codes. Background, foreground, muted, and border. Four words carry the entire theme.

Light mode and dark mode are not two systems. They are one system, tested twice.

## The Rules

No hardcoded colors. Ever.

Semantic tokens only: `foreground`, `background`, `muted`, and `border`. Use their scale variants for everything else.

Links look like links. Underline, color shift, or both. If it is not obviously clickable, it is not a link.

Code stays legible on any screen. Small viewport, same rules.

If it looks right in both themes, the system is right.

## Hierarchy

Three font families. One job each.

**Anybody** handles body copy. It is the primary reading face for paragraphs, descriptions, navigation, and interface text.

**Bebas Neue** handles display typography. Headings, large statements, and visual anchors use its condensed character.

**Fira Code** handles code. Technical examples use a monospace face to clearly separate implementation details from prose.

All three are loaded through `next/font/google` in the root layout.

## Text

68 characters wide.

Measure, leading, and size are tuned together, not separately.

Bold is not decoration. It is emphasis with intent.

The type system is intentionally small. Each family has one defined role.

```tsx

const serif = Bebas_Neue({
```

## Code Blocks

TypeScript, shell, and JSX use the same scroll-safe treatment with different
syntax highlighting. Monospace needs room to breathe.

### TypeScript

```ts
type ThemeTokens = {
  background: "bg-background";
  foreground: "text-foreground";
  muted: "bg-muted";
  border: "border-border";
};

export function formatDate(date: string): string {
  return new Date(date).toLocaleDateString(undefined, {
    year: "numeric",
    month: "short",
    day: "2-digit",
  });
}
```

### JSX

This is the route shape used by the current App Router and Velite setup:

```tsx
// app/blogs/[slug]/page.tsx
import { notFound } from "next/navigation";
import { getPostBySlug } from "@/lib/content";
import { MDXContent } from "@/components/mdx/mdx";

interface BlogPostPageProps {
  params: Promise<{ slug: string }>;
}

export default async function BlogPostPage({ params }: BlogPostPageProps) {
  const { slug } = await params;
  const post = getPostBySlug(slug);

  if (!post) notFound();

  return <MDXContent code={post.body} type="blog" />;
}
```

## Tables

Four tokens. Four jobs. No overlap.

| Token             | Job                       | Example                     |
| ----------------- | ------------------------- | --------------------------- |
| `bg-background`   | Page and primary surfaces | Main article background     |
| `text-foreground` | Primary text              | Headings and important copy |
| `bg-muted`        | Quiet fills               | Code and secondary surfaces |
| `border-border`   | Lines and outlines        | Cards and dividers          |

## Cards

A card is just content with edges. `border-border`, `bg-muted`, and

## Cursor States

The cursor has three modes: dot, invert, and takeover.

The dot needs no attribute. It is the default, not an afterthought. `invert`
turns the ring into a difference-blended highlight. `takeover` morphs to the
shape of the element it is hovering.

fills stay under 12% opacity. Let the text carry contrast, not the background.

## Rhythm

Spacing before richness.

A heading after a paragraph. A list after a heading. The eye should not notice
the transitions. It should just keep reading.

A paragraph before a heading.

### Heading follows paragraph

A paragraph after a heading. Then a list:

- An item with **bold emphasis**.
- An item with _muted emphasis_.
- An item with `inline code`.

Then a numbered list:

1. First.
2. Second.
3. Third.

## The Checklist

- Does it hold in light mode and dark mode?
- Do headings carry weight and do quotes carry voice?
- Do links look like links?
- Does inline code stay readable on small screens?
- Do custom MDX blocks sit consistently within the article column?

If every answer is yes, the system is done.

Systems do not get finished. They get maintained.
