# Typography & Color System

This post is an **MDX playground** for your blog styling. It exercises the full Tailwind Typography (`prose`) surface area while staying **theme-safe** (light/dark) through semantic tokens and neutral scales — no hardcoded hex values, no breakage on theme switch.

## The rules

What "theme-safe" means in practice:

- No hardcoded hex colors anywhere in component markup.
- Use **semantic tokens** (`foreground`, `background`, `muted`, `border`) and their scale variants.
- Links must be visually interactive — underline, color shift, or both.
- Code must be legible and scroll safely on small viewports.

> If this page looks good in both light and dark, your system is in a great place.

Headings use **DM Serif Display** at weight 400 with tight tracking. Body copy uses **Instrument Sans** at 400/500. Monospace uses **DM Mono**.

## Paragraphs, emphasis, and links

Regular paragraph text should read comfortably at a natural line length (`max-width: 68ch`). Measure, leading, and font size are all tuned together. Here is **bold**, *italic*, and ***bold italic*** used in context. Here is a [link to the blog index](/blogs) — it uses a thin underline that sharpens on hover.

Inline code like `pnpm velite:dev` and `app/blogs/[slug]/page.tsx` uses the `muted` background token with monospace type at 82% scale.

type ThemeTokens = {

### JSX

```tsx
// app/blogs/[slug]/page.tsx
import { getMdxContent } from "@/lib/mdx";
import { BaseMdx }       from "@/components/base-mdx";

export default async function BlogPost({ params }: { params: { slug: string } }) {
  const { content, frontmatter } = await getMdxContent(params.slug);

  return (
    <article className="prose dark:prose-invert mx-auto px-4 py-16">
      <h1>{frontmatter.title}</h1>
      <BaseMdx source={content} />
    </article>
  );
}
```

### Usage

```html
<!-- Blend dither -->
<button data-cursor="blend">Hover for blend</button>

<!-- Takeover -->
<div data-cursor="takeover" class="px-8 py-5 rounded-2xl border border-white/10">
  Hover me
</div>

<!-- Default dot — no attribute needed -->
<a href="#">Normal link</a>
```

## Final checklist

- Does the page feel correct in **light** and **dark** modes?
- Do headings have the right weight and serif face?
- Does inline code not break layout on small viewports?
- Do blockquotes read with a distinct editorial voice?
- Do `not-prose` blocks sit consistently within the prose column?
- Do links look clearly interactive?
